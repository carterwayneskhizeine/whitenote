# WhiteNote 帖子整理

你正在帮我整理 WhiteNote（一个微博客平台）导出的帖子。这些帖子以 markdown 文件的形式按 workspace 分文件夹存放。

### 文件格式

每个 .md 文件格式固定，不得改变结构：

```
#tag1 #tag2 #tag3

正文内容从第三行开始...
```

- 第 1 行：标签行，`#标签` 用空格分隔。没有标签则留空行
- 第 2 行：空行
- 第 3 行起：正文

解析器会提取第 1 行中所有 `#xxx` 作为标签，第 2 行起作为正文。如果你在第 1 行放了标题或段落文字，它们要么被当成错误标签，要么直接丢失。

### 红线规则（违反任何一条都会导致数据损坏）

1. **不能重命名文件** — 文件名在映射表中注册，改名后导入系统找不到文件
2. **不能移动文件** — 同上
3. **不能删除文件** — 数据库记录会变成孤儿
4. **不能新建文件** — 新文件没有映射，会被跳过
5. **不能编辑 .whitenote 文件夹里的任何东西** — 那是映射数据库
6. **不能修改评论子文件夹的名称或结构** — 文件夹名同样被追踪

你只能做一件事：**编辑 .md 文件的文本内容**（标签行 + 正文）。

### 目录结构示例

```
link_md/
├── Codes/
│   ├── .whitenote/workspace.json   ← 映射表，不要碰
│   ├── openclaw-流式响应总结.md      ← 帖子
│   ├── openclaw-流式响应总结/        ← 这个帖子的评论文件夹
│   │   ├── 日志分析-abc123.md       ← 评论
│   │   └── 修复方案-def456.md
│   ├── docker-端口占用.md
│   └── ...
├── OpenClaw/
│   └── ...
```

如果一个 .md 文件旁边存在同名子文件夹（去掉 .md 后缀），说明这个帖子有评论。**有评论的帖子不能被合并**，因为评论通过帖子 ID 关联。

### 整理任务

#### 1. 补全和统一标签

- 根据正文内容推断标签，补全缺失的标签
- 统一近义词标签（比如 `#docker-compose` 和 `#compose` 合并为 `#docker`）
- 中文内容用中文标签，英文内容用英文标签
- 优先使用已有标签，避免造新标签。以下是目前常用标签：

`#openclaw` `#docker` `#pnpm` `#clawdbot` `#volta` `#node` `#ragflow` `#electron` `#claude` `#telegram` `#windows` `#git` `#配置` `#ai` `#ai助手` `#api` `#moltbot` `#pinokio` `#powershell` `#命令行` `#安装` `#markdown` `#npm` `#workspace` `#同步` `#文档` `#clawx` `#gateway`

#### 2. 润色碎片化帖子

很多帖子非常短（< 50 字），只是一条命令、一句话备忘或零碎想法。对这些帖子：
- 如果内容自包含且有价值（如一条有用命令），保留原文，补好标签即可
- 如果是残句或上下文缺失的片段，标记 `#碎片` 标签，不要强行润色

#### 3. 合并同主题帖子

将同一 workspace 内属于同一话题的多个短帖合并为一个完整笔记。

合并方法：
- 选一个文件作为保留文件，把合并后的完整内容写进去
- 被合并掉的文件，将内容替换为（注意 `keeper-filename.md` 要替换为实际文件名）：

```
#merged

[merged into keeper-filename.md]
```

合并条件：
- 必须在同一个 workspace 文件夹内（不能跨文件夹合并）
- 必须确实属于同一话题（不要勉强合并）
- 被合并的帖子不能有评论子文件夹
- 合并后的正文要保留所有实质信息，按逻辑重新组织
